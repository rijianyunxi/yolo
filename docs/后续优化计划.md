## 2. 已完成改造

### 2.1 P0：数据安全与任务可靠性

- 标注标签采用临时文件 + `os.replace` 原子写入，并增加图片级进程内锁。
- 训练任务历史采用原子 JSON 写入；服务启动时将未完成的 `running/stopping` 任务标记为 `interrupted`。
- 预测任务使用 `runs/web_predict/<task_id>/` 隔离结果，持久化任务历史，详情只返回当前任务结果。
- 预测成功或取消后清理上传源文件；失败任务保留输入副本以支持重试，服务重启任务标记为中断。
- 导入 `.pt` 模型时执行实际加载预检，记录 SHA-256、任务类型、类别数和类别名；删除模型时清除元数据和缓存。
- 模型缓存 key 纳入文件修改时间和大小，并提供显式失效入口。
- 前端支持 `interrupted` 状态、预测轮询终态、模型类别数和保存提示。

### 2.2 P1：数据集检查与训练前置阻断

新增 `webui/services/dataset_check.py`，生成结构化报告并保存到：

```text
webui/reports/dataset_check_<profile>.json
```

检查项包括：

- train / val / test 图片和标签数量。
- 缺失标签、孤儿标签。
- 图片无法读取或损坏。
- 标签字段数量、数值、类别 ID、坐标和尺寸越界。
- 空标签文件。
- 过小标注框提示。
- 类别分布统计。
- 必需的 train / val 分组是否为空。

接口行为：

- `POST /api/tasks/check`：同步执行检查并返回报告。
- `GET /api/dataset/check`：读取最近一次报告。
- `POST /api/tasks/train-smoke`、`POST /api/tasks/train-full`：启动训练前自动检查；存在阻断问题时返回 HTTP 409，不启动训练。
- `scripts/check_dataset.py` 保留为命令行入口，不再创建不存在的目录。
- 数据集页展示通过/阻断摘要、类别分布和前 50 条问题详情。

## 8. 继续代码分析后的补充优化清单

本节基于当前工作区代码继续走查后补充，重点关注“功能已经能用，但在任务取消、长时间运行、大数据量和异常恢复场景下仍可能出现问题”的部分。以下内容是后续开发依据，不代表本轮已经完成。

### 8.1 P1：预测任务生命周期必须闭环

**当前代码位置：**

- `webui/services/predictions.py`
- `webui/routes/predictions.py`
- `webui/frontend/src/main.tsx` 中 `predict`、`pollPredictionTask`、预测任务列表相关逻辑

**已确认的现状和风险：**

1. 后端只有提交、查询、结果列表和删除接口，没有取消接口；`PredictionTask` 当前没有取消标志或取消事件。
2. 队列任务从 `queue.Queue` 取出后直接进入 `running`，前端无法区分“排队中取消”和“推理中取消”。
3. `run_prediction()` 内部同步调用 `model.predict()`。正在执行的 Ultralytics 推理无法被当前线程安全中断，强行杀进程也可能留下半成品结果目录。
4. 推理结束后无论成功还是失败都会删除上传源文件，失败任务因此不能直接重试。
5. 前端轮询只识别 `completed / failed / interrupted` 终态；如果后端以后增加 `cancelled`，前端必须同步更新终态判断，否则会持续轮询。
6. 预测结果目录写入 `runs/web_predict/<task_id>/`，但任务完成后不会自动回收；长期使用会使磁盘和 `/api/predictions` 扫描范围持续增长。

**建议的实现顺序：**

1. 为任务增加 `cancel_requested`、`cancel_reason`、`input_sha256`、`input_size`、`original_filename`、`duration_ms` 和 `schemaVersion` 字段。
2. 新增 `POST /api/predictions/tasks/{task_id}/cancel`：
   - `queued`：设置为 `cancelled`，从逻辑队列中跳过，立即清理上传文件。
   - `running`：设置为 `stopping` 并发送取消事件；当前推理调用完成后再转为 `cancelled`，不要在 Python 线程中强制杀线程。
   - `completed / failed / cancelled / interrupted`：返回当前任务，不重复执行。
3. worker 取任务后、加载模型前、调用推理前各检查一次取消事件；推理结束后再次检查，若已请求取消则清理本次输出并标记为 `cancelled`。
4. 新增 `POST /api/predictions/tasks/{task_id}/retry`，仅允许 `failed / interrupted`。重试必须创建新任务，原任务保持只读历史，不能复用原任务 ID。
5. 为失败任务保留受控的输入副本或任务专属缓存，成功/取消/重试保留期结束后再清理；不要继续依赖已删除的 `upload_path`。
6. 前端增加“取消”按钮、取消确认、取消中的状态提示、失败重试按钮，并把 `cancelled` 加入类型、状态文案和轮询终态。

**验收标准：**

- 队列中取消不会执行模型推理，任务历史保留 `cancelled` 记录。
- 推理中取消最终不会显示为 `completed`，且不会把半成品图片留在结果列表。
- 失败任务可以重试，重试会生成新的任务 ID，原任务的错误信息和耗时不被覆盖。
- 页面刷新或服务重启后，任务状态、取消原因和重试关联仍可读取。

### 8.2 P1：预测结果查询、删除和清理策略统一

当前 `/api/predictions` 只支持 `limit / since / until`，而任务记录已经包含 profile、模型来源和置信度。下一步应把结果记录和任务元数据关联起来，避免结果列表只能按文件修改时间查找。

**建议增加的查询字段：**

```text
GET /api/predictions?
  task_id=<id>&profile=<profile>&model=<model>&
  min_conf=<number>&since=<timestamp>&until=<timestamp>&
  limit=<number>&page=<number>
```

**结果记录建议补充：**

- `taskId`
- `profile`
- `modelSource`
- `modelPath` 或模型 SHA-256（不要只依赖可变文件名）
- `conf`
- `createdAt`
- `sizeBytes`
- `detectionCount`
- `outputDir`

**清理策略：**

1. 将结果目录清理独立为 service，不在路由中直接删除文件。
2. 删除前检查路径必须位于当前预测结果根目录；删除后返回成功、失败、未找到三类明细。
3. 增加“保留最近 N 个任务”“结果目录总大小上限”“按天清理”三种策略，默认只提示不自动删除，用户确认后再启用自动清理。
4. 清理任务与当前正在运行的预测任务隔离，避免删除正在写入的目录。
5. 缩略图缓存和预测结果都增加统计接口，展示文件数量、总大小和最早文件时间。

### 8.3 P1：训练任务状态和服务重启恢复继续收敛

`webui/services/tasks.py` 当前已经具备单任务限制、停止确认、`cancelled / failed / success / interrupted` 基础语义，但仍存在以下待完善点：

- `current_task` 只存在内存中；服务重启后历史可读，但无法自动接管仍在运行的外部进程。
- 历史 JSON 没有 schema 版本，后续增加字段时只能依赖宽松读取。
- 训练结果目录通过 `runName*` 和 `results.csv` 修改时间匹配，同名前缀目录较多时存在误匹配风险。
- 任务参数把资源快照、完整路径和命令全部返回前端，训练页直接 JSON 展示，信息过长时可读性较差。
- 路由层的停止逻辑仍直接修改 `task.status`、`task.stop_requested`，任务状态变更尚未完全集中到任务 service。

**后续方案：**

1. 任务记录统一增加 `schemaVersion`、`parentTaskId`、`cancelReason`、`lastHeartbeatAt` 和 `pid`。
2. 把 `request_stop()`、`mark_running()`、`mark_finished()`、`mark_interrupted()` 收敛到 `services/tasks.py`，路由只调用 service。
3. 启动时扫描任务记录和 PID：确认进程仍属于项目启动的命令后再标记为可恢复；无法确认归属时保持 `interrupted`，不自动接管。
4. 训练启动时记录唯一 `runDir`，后续指标只读取该目录，不再用模糊的 `runName*` 搜索。
5. 前端将训练参数、资源快照、结果目录拆成折叠区，任务列表只展示摘要。
6. 对历史 JSON 增加旧版本迁移函数，并为未知字段保留向后兼容读取能力。

### 8.4 P1：标注页面需要从“可用”进入“可验证”

当前在线标注功能已覆盖保存提示、筛选、分页、撤销重做和请求序列保护，但代码集中在 `webui/frontend/src/main.tsx`（约 2,279 行），后续维护风险较高。

**优先补齐：**

- 使用 Playwright 或 React Testing Library 覆盖：保存成功不刷新页面、保存失败保留未保存框、快速切换图片、筛选已标注/未标注、跨页上一张/下一张、撤销/重做和未保存确认。
- `api.ts` 的轮询请求统一支持 `AbortController`；页面切换、组件卸载和新一轮请求开始时主动取消旧请求。当前虽然使用 requestId 防止旧响应覆盖状态，但旧请求本身仍会占用连接和后端资源。
- 存请求增加客户端请求序列或图片 `mtime` 校验，避免多个浏览器窗口同时编辑时后写覆盖先写；冲突时返回 409 并提示用户重新加载（已完成，见第 28 节）。
- 将标注状态、图片分页缓存、撤销栈、保存动作拆到 `useAnnotation` hook；将任务轮询拆到 `useTaskPolling`，降低 `main.tsx` 的状态耦合。

### 11.1 预测任务状态机

新增并统一使用以下状态：

- `queued`：等待 worker 处理。
- `running`：正在加载模型或执行推理。
- `stopping`：收到取消请求，等待当前同步模型调用返回。
- `completed`：推理成功并生成结果。
- `failed`：推理异常，保留输入文件以支持重试。
- `cancelled`：用户主动取消；队列中的任务不会执行模型推理，运行中的任务采用协作式取消。
- `interrupted`：服务重启后恢复历史时，将未完成任务标记为中断。

新增接口：

```text
POST /api/predictions/tasks/{task_id}/cancel
POST /api/predictions/tasks/{task_id}/retry
```

取消不会强制终止 Python 线程中的 `model.predict()`；服务会在模型调用返回后检查取消事件，清理本任务结果目录并落盘最终状态。这样避免了强杀线程导致模型锁、文件写入或 CUDA 状态损坏。

### 11.2 预测元数据和失败重试

`PredictionTask` 和历史 JSON 增加：

- 原始文件名、输入 SHA-256、输入大小。
- 模型 SHA-256、置信度、耗时。
- 取消原因、取消请求标记。
- 重试父任务 ID、schema version。
- 结果图片对应任务、数据集、模型来源、检测数量、文件大小。

失败或服务中断任务重试时会创建新任务 ID，复制原始输入文件，继承 profile、模型选择和置信度；原任务保持只读历史，不会被覆盖。成功或取消后才清理输入文件，失败任务则保留输入文件，直到重试或后续清理策略处理。
